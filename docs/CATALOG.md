# Номенклатура и приёмка товара (каталог стройматериалов)

В этом документе описан справочный домен «товар/номенклатура» и документ
«Поступление» — как это устроено в реальных складских системах (WMS/ERP).

## Справочники

| Сущность | Файл | Назначение |
|----------|------|------------|
| `Category` | `server/src/category/` | Иерархический справочник категорий (Пиломатериалы → Доска обрезная → …). |
| `Manufacturer` | `server/src/manufacturer/` | Справочник производителей (название, страна). |
| `Unit` | `server/src/unit/` | Единицы измерения: код (`kg`, `m3`, …), название, символ (`кг`, `м³`, …). |

Справочники наполняются сидом при первом старте (`server/src/seed.ts`),
управляются через раздел **Справочники** (ADMIN).

## Номенклатура (`Product`)

Полная карточка позиции (`server/prisma/schema.prisma`):

- **Идентификация** — `sku` (артикул, автогенерация `ART-000001`), штрихкоды
  в таблице `Barcode` (EAN-13 — розничный, CODE128 — внутренние этикетки).
  Основной штрихкод генерируется автоматически, если не задан.
- **Классификация** — `categoryId`, `manufacturerId` (ссылки на справочники).
- **Единицы измерения** — `baseUnitId` (единица хранения) + `purchaseUnitId` /
  `saleUnitId` с коэффициентами пересчёта `purchaseToBase` / `saleToBase`
  (сколько базовых единиц в одной закупочной/продажной).
- **Цены** — `purchasePrice` / `estimatePrice` / `salePrice` (за базовую единицу)
  и `vatRate` (`NONE` / `VAT0` / `VAT10` / `VAT20`).
- **Физические атрибуты** — вес, габариты (мм), объём (м³), сорт, материал, ГОСТ.
- **Управление запасами** — `minStock` (точка заказа), `isActive` (архивация
  вместо физического удаления — сохраняет историю документов).

**Цены всегда хранятся за базовую единицу.** Пример: арматура хранится в `кг`,
закупается в `т` (1 т = 1000 кг). При приёмке 2 т по 41 000 ₽/т система
запишет в остатки 2000 кг по 41 ₽/кг.

## Приёмка (`GoodsReceipt`)

Документ «Поступление» с жизненным циклом `DRAFT → POSTED → CANCELLED`:

- Создание черновика со строками; строку можно добавить **по штрихкоду**
  (сканер) или выбором из каталога.
- Каждая строка хранит количество в базовой единице + единицу приёмки и её
  снимок-коэффициент (`unitId`, `unitQuantity`, `unitFactor`) — для честного
  отображения и пересчёта цены.
- **Проведение** (`POST /receipts/:id/post`) приходует товар на склад
  (увеличивает `StockItem.quantity` в базовых единицах).
- **Отмена** (`POST /receipts/:id/cancel`) возвращает остаток обратно.
- Удалять можно только черновик или отменённый документ.

## Эндпоинты

- `GET/POST /api/products`, `GET/PATCH/DELETE /api/products/:id`
- `GET /api/products/barcode/:value` — поиск по штрихкоду (сканер)
- `GET/POST /api/categories`, `…/manufacturers`, `…/units`
- `GET/POST /api/receipts`, `POST /api/receipts/:id/items`,
  `POST /api/receipts/:id/post`, `POST /api/receipts/:id/cancel`

## Кодогенерация

Бэкенд описывает контракт DTO + `@nestjs/swagger` → `openapi.json` →
`client/src/api/generated.ts`. После изменения DTO перегенерируйте:

```bash
cd server && npm run generate:openapi
cd client && npm run generate:api
```

> Примечание: в request-DTO (`*.dto.ts`) вложенные классы делайте **без `export`**
> и для enum-полей используйте `@IsIn([...])` с литеральным массивом — иначе
> плагин `@nestjs/swagger` генерирует битый абсолютный `require` на исходник.
